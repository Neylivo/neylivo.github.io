# Официальный сайт Ponoi

Исходник сайта [ponoiai.github.io](https://ponoiai.github.io/) — официального
сайта мессенджера **Ponoi (Поной)**.

Само приложение живёт в другом репозитории: **[ponoiai/ponoi](https://github.com/ponoiai/ponoi)**.
Веб-версия приложения — <https://ponoiai.github.io/ponoi/>. Этот репозиторий её
не касается вовсе, поэтому сайт нельзя сломать приложением, а приложение сайтом.

## Что здесь есть

```
build.mjs             сборка: из модулей страниц получается dist/
check.mjs             проверка собранного: ссылки, заголовки, описания, JSON-LD
src/site.mjs          адреса, навигация, общие подписи
src/layout.mjs        голова документа, шапка, подвал
src/release.mjs       сведения о последнем выпуске (версия, файлы, размеры)
src/changelog-data.mjs история версий из репозитория приложения
src/llms.mjs          llms.txt
src/pages/*.mjs       по модулю на страницу, обе языковые версии в одном файле
assets/               стили, единственный скрипт, знак, значки, картинка для соцсетей
data/                 сохранённые ответы GitHub — чтобы сборка не падала без сети
scripts/og.cjs        перерисовать картинку для соцсетей (нужен electron)
scripts/look.cjs      снимки всех страниц на экране и на телефоне (нужен electron)
```

Ни сборщика, ни фреймворка, ни зависимостей: `package.json` тут нет намеренно.
Сайт из пятнадцати страниц, которые обязаны читаться поисковым роботом без
единой строчки JavaScript, — ровно та задача, где фреймворк добавляет сборку,
гидрацию и способы всё это сломать, не добавляя ничего нужного.

## Собрать

```bash
node build.mjs    # → dist/
node check.mjs    # проверить собранное
```

Открывать `dist/index.html` файлом бесполезно: внутренние ссылки абсолютные
(`/about/`). Нужен любой статический сервер, например:

```bash
npx serve dist
```

Посмотреть глазами, включая телефонную ширину и светлую тему, — снимки всех
страниц:

```bash
../ponoi/node_modules/.bin/electron scripts/look.cjs   # → dist-look/
```

## Откуда берётся версия

Кнопка «Скачать» обязана вести на файл, а не на страницу GitHub. Имя файла
содержит версию (`Ponoi-Setup-1.556.1.exe`), поэтому один раз написать её руками
нельзя — через месяц сайт раздавал бы устаревшее приложение.

Версия, размеры и ссылки берутся при каждой сборке из последнего выпуска
`ponoiai/ponoi`. Сборка запускается при изменении сайта, по кнопке **и каждые
шесть часов** — иначе о новом выпуске в соседнем репозитории здесь никто бы не
узнал. Если GitHub недоступен, берётся `data/release.json` из репозитория:
сборка не падает и сайт не выкладывается без кнопки скачивания.

Чтобы сайт обновлялся не через шесть часов, а сразу после выпуска, в
`ponoiai/ponoi` можно добавить в конец релизного процесса такой шаг:

```yaml
- name: Обновить сайт
  env:
    GH_TOKEN: ${{ secrets.SITE_DISPATCH_TOKEN }}   # PAT со scope repo
  run: |
    gh api repos/ponoiai/ponoiai.github.io/dispatches \
      -f event_type=ponoi-release
```

Без этого шага всё работает, просто с задержкой до шести часов.

## Правила, которых держится содержание

1. **Ни одного утверждения без кода за ним.** Всё, что сайт говорит о
   безопасности и приватности, соответствует
   [аудиту](https://github.com/ponoiai/ponoi/blob/main/SECURITY_ARCHITECTURE_AUDIT.md)
   и коду приложения. Не реализовано — не написано.
2. **Никаких выдуманных чисел.** Ни пользователей, ни сообществ, ни оценок, ни
   наград, ни отзывов. Их не существует, и придумывать их нельзя.
3. **Слабые места названы.** Для этого есть отдельная страница
   [/transparency/](https://ponoiai.github.io/transparency/), и она не приписка
   в конце, а часть содержания.
4. **Одна сущность.** Везде «Ponoi» и «Поной» — одно и то же; «Ponoi AI»,
   «Ponoi Inc.» и прочих не бывает. Формулировки лежат в
   [/press/](https://ponoiai.github.io/press/).
5. **Ничего с чужих серверов.** Ни шрифтов, ни скриптов, ни счётчиков: сайт о
   приватности не должен сообщать чужому серверу IP своего читателя.
